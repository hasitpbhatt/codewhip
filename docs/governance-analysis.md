# CodeWhip Governance Analysis — Policy, Audit, Sandbox, Secrets

## Summary
CodeWhip ships a minimal but functional governance core: hash-chained audit log, harness-side policy denials, path jail for file tools, and a loop that never trusts the model. Gaps remain between the design documented in `docs/moat/03-governor.md` and the implemented code, especially around policy-as-code, serve-proxy safety, and secrets handling.

## What is implemented

### Policy enforcement
* `src/policy.ts` implements a fail-closed permission ladder with non-overridable denylist, shell chaining/worktree-escape denials, and ask/allow defaults.
* Promoted denies from `policy.md` are pre-flight, harness-side.
* `codewhip-policy.yaml` exists but is not parsed — current schema is 10 lines and unused by the runtime.

### Append-only audit
* `src/audit.ts` appends JSONL to `.codewhip/audit.log` with `v,seq,ts,runId,actor,tool,args_hash,result_hash,prev_hash,policy,sig`.
* Ed25519 signing with repo keypair generated by `init`. `verifyChain`, `buildBundle`, `--last/--replay` semantics exist.
* Audit is senior to memory: `appendEntry` is called per tool call in `loop.ts`.

### Sandbox v1
* File tools use `src/tools/jail.ts` realpath jail.
* Bash uses string-based `matchWorktreeEscape` + denylist + chaining regex. No microVM.
* `--yolo` is explicit, logged, bannered. Actor = `yolo`.

### Secrets redaction
* `src/redact.ts` regex-based scrubbing at model boundary and share bundle.
* `*.env*` reads are denied by policy store logic.

## Gaps

### 1. Policy-as-code is not policy-as-code
* `codewhip-policy.yaml` is never loaded. Enforcement is hard-coded in `policy.ts`:
  `DENY_PATTERNS`, `SAFE_BASH_PREFIXES`, defaults.
* Documented schema: `version, defaults, rules[]` with action/resource/effect, LAST-match-wins, require tests/approvals — not implemented.
* No path/command pattern matching from YAML, no test-gate on prod paths, no `external` action enforcement.
* `codewhip-policy.yaml` example in repo is 10 lines; mismatch with docs.

### 2. Audit coverage gaps
* Agent loop audit is solid. Serve proxy `src/serve.ts` writes **no audit entries**. It is explicitly documented as “executes no tools, applies no policy”. The audit schema is frozen for H1, so serve stays out of `audit.log` by ruling — every serve chat call is still recorded in `provider-analytics.jsonl` via the port layer, which feeds `/stats` and auto-routing health.
* The raw-body console logger that used to sit on the serve request path was removed: serve persists no request bodies anywhere. Every serve chat call records only outcome buckets (`ok/auth/quota/timeout/network/bad_model/other`), never content.
* No audit of auth UI key writes, custom provider registration, or serve requests.

### 3. Serve proxy governance
* Serve proxy is an OpenAI-compatible key holder. It binds 127.0.0.1 by default and requires `--token` for non-loopback. Good.
* Keys are never echoed in JSON responses. Good.
* No redaction of secrets before forwarding to upstream provider. User prompt containing API keys is forwarded verbatim.
* No policy check on incoming messages. Serve is intentionally policy-free, but that means a compromised client can exfiltrate provider keys via the proxy? Keys never leave process, but messages can contain secrets.
* Request body size cap 4MB, no rate limiting, no per-IP allowlist.
* Serve logs no request bodies (the former request-logging hook is deleted).

### 4. Secrets and provider keys
* Provider keys resolved via env > `configDir/credentials.json` > anonymous. File mode 600, dir 700. No encryption at rest.
* `redactSecrets` patterns are best-effort regex; misses many formats, false positives on high-entropy strings.
* `redactEnvValues` is only used on share path, not on loop transcript push.
* No automatic rotation/revocation detection for provider keys.
* Custom provider registration accepts user-supplied URLs; validation exists but no policy gate.

### 5. Sandbox limitations
* Bash jail is string-based, not realpath. `matchWorktreeEscape` regex can be bypassed via encoding, globs, or subshell tricks.
* No OS-level isolation. Documented honestly as “harness jail, not OS isolation”.
* No network sandbox for `webfetch` beyond ask-default. No egress allowlist enforcement.
* `--yolo` bypasses policy checks but still denies non-overridable denylist. Audit records actor=yolo. Acceptable per design.

### 6. Memory / policy promotion
* Promoted denies compile to `policy.md`, not `codewhip-policy.yaml`. Schema divergence.
* `remembered.jsonl` provenance fields exist, good.

## Design recommendations

### Policy schema v1 enforcement
Load `codewhip-policy.yaml` with LAST-match-wins:
```yaml
version: 1
defaults: {effect: ask}
rules:
  - action: read   resource: "**"               effect: allow
  - action: edit   resource: "src/**"           effect: allow
  - action: edit   resource: "**/*.env*"        effect: deny
  - action: shell  resource: "git status *"     effect: allow
  - action: shell  resource: "rm -rf *"         effect: deny
```
Implement matcher with glob for paths, prefix for commands, deny > ask > allow per match set.

### Append-only audit for serve
* Serve stays out of `audit.log` (frozen H1 schema, no new actor values). Provider-analytics remains the serve-side record: outcome buckets only, never content.
* Never log raw bodies. Serve persists no request bodies at all.

### Sandbox v1 hardening
* Keep string denylist, add realpath check for bash `cd`-style commands by resolving cwd after exec? Harder. Document limitation.
* Add command canonicalization before regex.
* For serve proxy, keep loopback + token gate, add optional per-request HMAC, redact secrets on ingest.

### Secrets hygiene
* Scrub incoming serve request body before forwarding: run `redactSecrets` on `messages[*].content` with a policy flag `redact_user_secrets`. Opt-in.
* Never log raw bodies. Replace `logServeRequest` with redacted-only logging.
* Store credentials with OS keychain fallback where available; keep file fallback.

### SOC2 story
Auditor bundle already exists via `audit --export`. Extend to include serve access logs and policy snapshot hash.
