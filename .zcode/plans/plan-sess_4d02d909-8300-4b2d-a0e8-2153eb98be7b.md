# Fix dead playground UI + auto as instant default

## Root cause (confirmed live in browser)
The playground's entire inline script fails to parse — `SyntaxError: Invalid or unexpected token` — so nothing runs: no model fetch, no "auto" option, no Send/refresh handlers. Badge shows "loading…" forever. Cause: in `playgroundHtml()` (backtick template literal), `src/serve.ts:921` writes `buf.split('\n')`; the TS template consumes the `\n` escape, so the served page contains a raw line break inside the JS string (`buf.split('` ⏎ `')`). Server endpoints are fine and fast (verified: /v1/models 200 in ~0.7s, catalog cached 60s — no per-request recompute).

## Changes

1. **Fix the syntax bug** — `src/serve.ts:921`: escape for output, not for the template:
   `const lines=buf.split('\\n'); buf=lines.pop();`

2. **"auto" always available + default** — `src/serve.ts` playgroundHtml:
   - Static markup (line ~814): `<select id="model" ...><option value="auto" selected>auto — health-weighted pick</option></select>` so the page is usable the instant HTML arrives, even before/without the model list.
   - `renderModels()`: keep rebuilding the list as today; after rebuild, if there is no valid saved `localStorage` choice, explicitly select `auto` (keep the existing saved-preference behavior otherwise; auto stays first and is dropped only when an active filter excludes it — unchanged semantics).

3. **Prevention test** — `src/serve.test.ts`: new test(s) that GET `/playground` (and `/auth`) from the existing test server, extract inline `<script>` blocks, and `new Function()`-compile each — this exact bug class fails CI from now on. Also assert the served `/playground` HTML contains the static `<option value="auto" selected`.
