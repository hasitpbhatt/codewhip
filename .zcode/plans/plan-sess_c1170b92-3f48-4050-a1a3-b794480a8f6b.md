# Subagents & Delegation — B then C, read-only children

## Requirement
Sequential single-loop execution is the bottleneck: exploration, multi-perspective review, and convergence happen serially. Claude Code/OpenCode/Gemini/Codex all ship delegation; their shared weaknesses are black-box child runs (unauditable), permission bypass (user @-mention), and context bloat. Codewhip's global hash-chained audit (seq/prev_hash derived from tail per append, mkdir-locked) means nested `agentLoop()` calls compose into the chain automatically — the committee's kill-list objection was based on a misreading. Goal: delegation that is *more* trustworthy than competitors', not a port of theirs.

## Design (locked decisions)
- **Stage B**: one `delegate` tool + declarative agent files `.codewhip/agents/*.md` (YAML frontmatter: `name`, `description`, optional `model`, `max_steps`; body = system prompt). 3 built-ins (explore, review, plan) so it works zero-config. Model picks by description; delegation is model-driven only (no user bypass — OpenCode's flaw is designed out).
- **Stage C**: `delegate_many` tool — `{entries: [{agent, task}...]}` capped at 4 concurrent children, ordered results back, parent converges. The committee use case.
- **Children are read-only** (plan-mode semantics): read/search/webfetch only, edit/write/bash/delegate pre-refused before the ask ladder. No ask prompts inside children (the ladder never fires). Depth 1: children cannot delegate.
- **Context isolation**: fresh transcript per child (system = agent file body + task), no parent history. Summary-only result passing: child's final `text`, redacted + capped (reuse `TOOL_OUTPUT_CAP`).
- **Auditability**: every child tool call lands on the global chain with the child's own runId (zero audit.ts changes); child writes its own outcome record; parent's outcome references child runIds in its trace. This is the beat-Claude-Code feature: fully auditable children.
- **Receipts**: child usage folds into the parent's `usageByModel` buckets (per provider:model, honest est. marks preserved) — no hidden spend.
- **Visibility**: child events forwarded to parent's `onEvent` prefixed `[<agent>]` so the user sees live progress (Don Norman's visibility principle).
- **Memo**: `delegate`/`delegate_many` NOT added to `IDEMPOTENT_TOOLS` — never memoized.
- **Plan mode**: parent `--plan` refuses `delegate`/`delegate_many` (read-only runs spawn no children).

## Architecture (minimal seam, verified against source)
1. `ToolContext` (src/tools/types.ts): add `port?: ChatPort; model?: string; label?: ProviderId; depth?: number`. Loop passes them at the exec site (loop.ts:584) — the single load-bearing change.
2. `ToolName` union + `lookupTool` list (loop.ts:121-126) + `toolSpecs()` grow `delegate`/`delegate_many`. Child tool filtering: `toolSpecs(depth)` excludes delegate tools + mutating tools for children (transcript/failover assume same specs — filter at construction, not per call).
3. New `src/subagents.ts`: agent-file parser (frontmatter + body), built-in agent registry, `runChildAgent()` that builds child `LoopArgs` (fresh runId via its own agentLoop call, `planMode: true`, `remembered: listRules(cwd)`, parent's `signal`, smaller default `maxSteps` = 10) and returns `{text, runId, usageBuckets, childRunIds}`.
4. `src/tools/delegate.ts` + `delegate_many.ts`: thin tools over `runChildAgent`; `delegate_many` runs children via `Promise.all` with concurrency cap 4 (stagger-free; per-child rotation already exists).
5. `checkPermission` (src/policy.ts): explicit `deny` branch for delegate tools when depth > 0 (belt) — plan-mode pre-ladder refusal (loop.ts:448) extended to name delegate tools (suspenders).
6. index.ts: no new flags; `--plan` banner mentions no-delegation. Receipt line unchanged (buckets absorb children).

## Implementation order (each stage shippable)
- **B1**: ToolContext seam + depth plumbing + plan-mode refusal naming delegate.
- **B2**: `src/subagents.ts` — parser, built-ins (explore/review/plan), `runChildAgent`.
- **B3**: `delegate` tool + policy branch + toolSpecs filtering + event forwarding + usage aggregation.
- **C**: `delegate_many` with concurrency cap + ordered aggregation.
- **Docs**: CHANGELOG, README section, roadmap line, `codewhip help run`.

## Validation
- Committee re-review (six personas) after Stage B and after Stage C, per the working agreement.
- End-to-end: `codewhip run "review src/loop.ts for bugs"` → observe `[explore]` child events, verify audit chain intact (`audit --verify`), child outcome records exist, parent receipt includes child tokens.
- Convergence demo: a run that fans out 3 reviewers and converges — the user's committee use case.

## Testing
- Unit: agent-file parser (valid/malformed/frontmatter missing), depth guard (child delegate refused), child tool filtering (mutating tools absent from child specs), summary cap/redaction, usage bucket merge, delegate_many ordering + concurrency cap, plan-mode refusal, memo exclusion.
- Loop integration (existing harness pattern): child runId appears in global audit chain; child outcome record written; parent trace references child; `--plan` parent refuses delegation; checkpoint untouched by read-only children.
- Full suite green (currently 250), lint + typecheck + build per repo definition of done.

## Explicit non-goals (v1)
Mutating children, background/fire-and-forget delegation, nesting beyond depth 1, user @-mention invocation. Mutating children get a design pass later (checkpoint/rollback semantics per child are already sound — per-runId dirs).
