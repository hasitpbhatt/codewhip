## stepfun "key not working" debug (22:09 PDT) — ROOT CAUSE FOUND
User ran `codewhip models stepfun` -> key rejected. Initial (WRONG) conclusion was
"invalid key"; corrected after testing the EXACT stored key against BOTH hosts:
- api.stepfun.com: 401 "Incorrect API key provided" (rejects the valid key)
- api.stepfun.ai:  GET /v1/models -> 200 (real catalog: step-3.5-flash,
  step-3.7-flash, stepaudio-2.5-*, step-image-edit-2); POST /v1/chat/completions
  -> 402 quota_exceeded (auth PASSES, account just has no quota/billing)
So StepFun serves API on both hosts but KEY AUTH IS BOUND TO THE .ai BACKEND;
a valid key 401s on .com. codewhip was configured with baseUrl api.stepfun.com ->
every call failed. FIX: changed stepfun.baseUrl src/provider.ts to
"https://api.stepfun.ai" (updated comment + rebuilt; dist verified). `codewhip
models stepfun` now lists 9 models. Remaining user-side issue: 402 quota ->
account needs active plan/free-tier activation at platform.stepfun.com.

wrong-host/auth-namespace mismatch. Note: resolveKey trims `auth login` input but

file outside the user's normal shell.

## stepfun chat 402 (22:4x PDT) — account quota, NOT a code bug
After the host fix, `codewhip models stepfun` works (200) BUT every chat returns
`402 quota_exceeded` ("You exceeded your current quota") for ALL models
(step-3.5-flash AND step-3.7-flash). This is account-level: StepFun gates the
OpenAI-compatible API (api.stepfun.ai) behind a plan/quota, while the in-console
playground (studio.stepfun.ai) uses a browser session and stays free. So "playground
works" does NOT mean the API key has quota. Fix is on StepFun's side: activate an
API plan / add billing at platform.stepfun.com. Nothing to change in codewhip.
